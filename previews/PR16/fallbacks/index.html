Rule fallbacks

Where no rule fits, an engine may consult a rule fallback instead of reporting the error. A rule fallback is a callable, fallback(node, target, args), that takes the node, the target and the rule's arguments. It returns a message, or nothing when it has none either.

An engine consults the fallback only when resolution returns a RuleNotFound. A fallback therefore never replaces a rule that exists, and an error inside a rule is never turned into a fallback. ReactiveMP takes a fallback as its activation option rulefallback. A message that a fallback computes has an undefined log scale, unless the fallback declares it by returning with_logscale(message, logscale). A fallback may also say how it computed its answer, for an engine's events and a report to read, by returning with_outcome(answer, outcome).

The node function fallback

NodeFunctionRuleFallback is the fallback this package provides. Called on its own, it applies to a stochastic node without groups; an engine, which passes it more (see below), gets more. Its message towards a target is the node's log-density as a function of the target, with every other input collapsed to a point, by default its mean. The message is a NodeFunctionLogPdf, an unnormalised log-density. A form constraint, or a product with a proper distribution, turns it into a distribution.

The node below is a normal distribution given by a function of its mean and variance. It has no rules at all:

using MessagePassingRulesBase, BayesBase, ExponentialFamily

gaussian(μ, v) = NormalMeanVariance(μ, v)   # the distribution of out, given μ and v

@define_factor_node(node = gaussian, type = Stochastic, interfaces = [:out, :μ, :v])

fallback = NodeFunctionRuleFallback()
args = MessagePassingRulesBase.RuleArgs(m = (out = PointMass(2.0),), q = (v = PointMass(0.5),))
message = fallback(gaussian, MessagePassingRulesBase.Target(:μ), args)

logpdf(message, 1.0), logpdf(NormalMeanVariance(1.0, 0.5), 2.0)
(-1.5723649429247002, -1.5723649429247002)

The fallback's message towards μ evaluates the node's log-density, $\log \mathcal{N}(2 \mid \mu, 0.5)$, at $\mu = 1$. The observation out = 2 and the variance v = 0.5 were collapsed to their means. An input that is not a point mass is collapsed the same way:

args = MessagePassingRulesBase.RuleArgs(m = (out = NormalMeanVariance(2.0, 3.0),), q = (v = PointMass(0.5),))
logpdf(fallback(gaussian, MessagePassingRulesBase.Target(:μ), args), 1.0)
-1.5723649429247002

The message on out has the mean 2.0, so the result is the same. Its variance is lost.

Where the fallback has nothing

Called with three arguments, the fallback returns nothing for a deterministic node, a node with groups, a member of a group, or an input that is a joint marginal. A deterministic node has no log-density:

julia> using MessagePassingRulesBase

julia> struct Plain end

julia> @define_factor_node(node = Plain, type = Deterministic, interfaces = [:out, :in])

julia> NodeFunctionRuleFallback()(Plain, MessagePassingRulesBase.Target(:out), MessagePassingRulesBase.RuleArgs(m = (in = 1.0,))) === nothing
true

What an engine passes to a fallback

An engine consults a fallback through call_fallback for a message or a marginal, and call_energy_fallback for an average energy, with the node's algorithm and the RuleContext its rules receive. A three-argument fallback is asked about messages only. With the full signature, NodeFunctionRuleFallback also serves:

  • a deterministic node, through its function getnodefn(ctx.node, Target(:out)): towards an input, the message on out pulled back through the function, the other inputs plugged in; towards out, the function at the plugged-in inputs, a point mass;
  • a node with groups, a member of a group included;
  • the average energy of a stochastic node whose interfaces each have a marginal, -E_q[log f], computed by the expectation backend ctx.expectation when the engine supplies one.
MessagePassingRulesBase.NodeFunctionRuleFallback — Type
NodeFunctionRuleFallback(extract = mean)
(fallback::NodeFunctionRuleFallback)(node, target, args::RuleArgs)

A rule fallback: the message a stochastic node sends when no rule matches, computed from its nodefunction, the log-density its declaration defines. The message towards out or another interface is the node's log-density in that interface, every other input, a message or a marginal, collapsed to a point by extract. It is a NodeFunctionLogPdf, unnormalised, which a form constraint or a product with a proper distribution turns into one. Its log scale is undefined.

Arguments

  • extract: the function collapsing each input to a point. Default: mean.

Returns

Called as fallback(node, target, args): a NodeFunctionLogPdf, or nothing where the node function does not apply: a deterministic node, a node with groups, a member of a group, an input that is a joint, or an interface other than the target that has no input. Consulted by an engine through call_fallback, with the node's rule context, it also serves deterministic nodes, through the node instance's function, and members of groups; through call_energy_fallback it gives the average energy -E_q[log f] of a mean-field cluster.

An engine consults a fallback only when resolution finds no rule, so an error inside a rule is never turned into a fallback; ReactiveMP takes it as the activation option rulefallback. A fallback of one's own is any callable of (node, target, args) returning a message or nothing, or a type with its own call_fallback method, which also receives the node's algorithm and rule context and may answer for marginals and average energies.

Examples

fallback = NodeFunctionRuleFallback()
message = fallback(NormalMeanVariance, MessagePassingRulesBase.Target(:out),
                   MessagePassingRulesBase.RuleArgs(m = (μ = PointMass(0.0), v = PointMass(1.0))))
logpdf(message, 0.5)   # logpdf(NormalMeanVariance(0.0, 1.0), 0.5)

MessagePassingRulesBase.NodeFunctionLogPdf — Type
NodeFunctionLogPdf(logpdf)

A message given by an unnormalised log-density, supported everywhere: the message a NodeFunctionRuleFallback computes, and the form other rule fallbacks give theirs, such as a log-density pulled back through a deterministic function or averaged over other inputs. BayesBase.logpdf(d, x) and d(x) are both logpdf(x), and insupport(d, x) is always true.

MessagePassingRulesBase.call_fallback — Function
call_fallback(fallback, node, target, algorithm, ctx, args)

How an engine consults a rule fallback when resolution finds no rule for a message or a marginal: with the node, the target, the node's algorithm, the RuleContext its rules receive and the arguments. The default asks a three-argument fallback, fallback(node, target, args), about messages only (Target, IndexedTarget), and answers nothing for a marginal (ClusterTarget): a fallback written for messages is never asked about anything else. A fallback that wants the algorithm or the context, such as the node instance ctx.node or the expectation backend ctx.expectation, adds a method of its own for its type, leaving the target untyped or typing it: call_fallback(::MyFallback, node, target, algorithm, ctx, args).

A fallback that knows the log scale of its message returns with_logscale(message, logscale), which the engine takes apart with unwrap_fallback; any other message has an undefined log scale.

See also call_energy_fallback, NodeFunctionRuleFallback.

source
MessagePassingRulesBase.call_energy_fallback — Function
call_energy_fallback(fallback, node, algorithm, ctx, args)

How an engine consults a rule fallback when no average energy is defined for a node, a term of the free energy: nothing by default, so that a fallback written for messages leaves the free energy as it was. See call_fallback.

MessagePassingRulesBase.unwrap_fallback — Function
unwrap_fallback(answer) -> (result, logscale)

What an engine does with a fallback's answer: the result and its log scale. A fallback that knows its message's log scale returns with_logscale(message, logscale), a number or an UndefinedLogScale with its reason, such as :unnormalised_product for an unnormalised density whose normaliser a form constraint computes; any other answer has the log scale UndefinedLogScale(:fallback).

source
MessagePassingRulesBase.with_outcome — Function
with_outcome(answer, outcome)

Pair a rule fallback's answer, a message, a joint marginal or an average energy, with how the fallback computed it: plain data, such as (method = :joint_laplace, converged = true, iterations = 6), which an engine hands on to its events and a report reads. The answer may itself be with_logscale(message, logscale); with_outcome goes outside it.

See also unwrap_outcome.

source
MessagePassingRulesBase.unwrap_outcome — Function
unwrap_outcome(answer) -> (answer, outcome)

What an engine does first with a fallback's answer: the answer without its outcome, and the outcome a fallback declared with with_outcome, nothing for any other answer. The answer then goes to unwrap_fallback for a message.

source
MessagePassingRulesBase.WithOutcome — Type
WithOutcome(answer, outcome)

A rule fallback's answer paired with how it was computed, as with_outcome builds it. An engine takes it apart with unwrap_outcome before anything else; no rule receives one.
